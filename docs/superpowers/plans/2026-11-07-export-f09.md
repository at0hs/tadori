# Excel 出力（F-09） Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 誰でも S-12 から実行記録を .xlsx でダウンロードでき、客先への証跡としてそのまま開いて印刷できるようにする。

**Architecture:** API は `GET /api/executions/:id/export`。既存の `getExecution` で詳細を読み、ExcelJS でブックを組み立てて返す。ExcelJS を使うのは `server/src/features/executions/export-workbook.ts` だけにする（D-63）。ファイル名・日時の整形は ExcelJS に依らない純粋な関数に分ける。画面は S-12 の見出しの操作に「Excel に出力」を足し、取得した Blob をファイルとして保存させる。

**Tech Stack:** Hono、ExcelJS 4.4.0（新しく入れる。server だけ）、Zod 4、React 19、TanStack Query、shadcn/ui（Base UI の `dropdown-menu`）、Vitest、Playwright。

**Spec:**
- レイアウト・ファイル名・S-12 の操作：`../tadori-docs/design/ui.md` 8.9（と 8.4 の操作の表、8.8 のエラー）。
- API：`api.md` 5.3（`GET` だが操作ログを出す）、5.1（手順書名は版の文書から）。権限：`authorization.md`（Excel 出力は全員）。承認者の出し方：`data-model.md` 4.3。マスク：`data-model.md` の表（Excel 出力はサーバーで常に `●●●●`）。
- 要件：`../tadori-docs/requirements.md` F-09、F-10。設計判断：D-01、D-23、D-43、D-63。

## Global Constraints

- ブランチは `feat/export-f09`（main から）。コミットは Task ごと。範囲外：ホーム（S-03）、本番用の compose・Dockerfile。
- ExcelJS は `exceljs@4.4.0` に固定（`^` を付けない）し、`@tadori/server` の dependencies に入れる。`import` するのは `export-workbook.ts` とそのテストだけ。
- 依存の `uuid` の脆弱性の知らせ（GHSA-w5hq-g745-h8pq）：`pnpm audit` で直った版を確かめ、ExcelJS の動く範囲で上げられるなら `pnpm-workspace.yaml` の `overrides` で上げる。上げると Task 2 のテストが落ちるなら上げず、PR に理由を書く。
- シート名「実行記録」、1枚だけ。枠線を消す。文字は Meiryo UI 10pt、コマンドの列だけ Consolas 9pt。罫線は細い灰色。ラベルと明細の見出しは灰色の地・太字。
- 日時は日本時間の `YYYY-MM-DD HH:mm` の**文字列**で入れる（Excel の日付型にしない）。
- 秘密変数は `●●●●`（`SECRET_MASK`）。サーバーは値を持たないので、置換で必ずマスクになる。
- ラベルは「承認者」（「承認した人」ではない）。承認者・承認日時は `approvalStatus === "approved"` のときだけ出す。
- 状態の表示名：ステップ 未実施／完了／スキップ／失敗、実行 実行中／完了／異常終了／中止、承認 承認待ち／承認済み／差し戻し、承認状態がなければ「—」。区分 手順／切り戻し。
- 操作ログ：`execution.exported`（`target: { type: "execution", id }`）。ファイルの中身や名前はログに出さない。
- 画面：色は CSS 変数だけ。画面の移動ではないのでボタンでよい。失敗は S-12 の見出しの下の帯に出す（8.8）。

## Review Focus

1. **手順書名に Windows で使えない文字や改行、絵文字、とても長い名前がある**：保存できるファイル名になり、ブラウザに日本語の名前で届く → Task 1 の `exportFileName`・`contentDisposition` のテスト、Task 3 の `fileNameFromDisposition` のテスト。
2. **コメント・エビデンスにマスク済みの `●●●●` や長い複数行のテキスト、`=` で始まる文字列がある**：そのまま文字として出て、数式として解釈されない → Task 2「本文が = で始まっても文字列のまま」。
3. **実行中・中止・差し戻しの実行**（終了日時・承認者がない）：空や「—」になり、差し戻した人を承認者として出さない → Task 2 の表の該当行。
4. **閲覧者ロールだけの人・自分の実行でない人が出力する**：出力できる（Excel 出力は全員）→ Task 2「閲覧者も出力できる」、Task 3 の `exportPlacement` のテスト。
5. **出力に失敗した（通信の失敗・削除済みの ID・セッション切れ）**：帯に出し、ボタンは押せる状態に戻る → Task 3 の `onError`、Task 4 の E2E は成功の流れだけ（失敗は手で確かめる）。
