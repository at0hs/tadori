# 承認・差し戻し・再依頼（F-08） Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 承認者が終了した実行を S-12 で承認・差し戻しでき、差し戻された実行は本人がコメントとエビデンスを追記して再依頼できるようにする。

**Architecture:** API は `server/src/features/approvals/`（api.md 4.5、conventions.md 1章）に置き、`/api/executions` に同じ前置きで載せる。実行の行を `FOR UPDATE` でロックしてから、職務分離・承認状態を確かめ、`executions` と `approval_events` を同じトランザクションで更新する（data-model.md 4.3）。画面は S-12 の見出しの右に操作を出し分け、ダイアログは既存の `Shell` を使う。帯と承認の履歴は F-04〜F-06 で作り済み。

**Tech Stack:** Hono、Drizzle 1.0 RC、Zod 4、React 19、TanStack Query、shadcn/ui（Base UI の `alert-dialog`）、Vitest、Playwright。新しい依存は入れない。

**Spec:**
- 画面：`../tadori-docs/design/ui.md` 8.4（見出しの操作の表・帯）、8.7（承認の確認・差し戻し・再依頼のダイアログ）、8.8。見た目の正本は `../tadori-docs/design/mockups/executions.html`。
- API：`api.md` 4.5。状態と操作：`state-transitions.md` 5章（と 4章のコメント・エビデンスの条件）。権限：`authorization.md` 3.4。ログ：`conventions.md` 6章。
- 要件：`../tadori-docs/requirements.md` F-08、4.1。設計判断：D-08、D-31、D-35、D-43、D-56。

## Global Constraints

- ブランチは `feat/approvals-f08`（main から）。コミットは Task ごと。
- 範囲外：Excel 出力（F-09。「⋯」の「Excel に出力」と、「それ以外」の人の「Excel に出力」のボタンも F-09 で足す）、ホーム（S-03）。
- 値の名前：承認 `pending` / `approved` / `rejected`、承認の履歴 `requested` / `approved` / `rejected`。
- 差し戻し・再依頼のコメント：前後の空白を取って必須、5000 文字まで（コメントと同じ上限）。承認にはコメントがない。
- 職務分離：承認・差し戻しは承認者ロールで、実行者でない人だけ（自分の実行は `FORBIDDEN`）。再依頼は本人（D-35）だけ。
- エラーの順：ロールがない → 403（`requireRole`）、実行がない → `NOT_FOUND`、本人・職務分離に反する → `FORBIDDEN`、承認状態が合わない → `STATE_CONFLICT`、コメントがない → `VALIDATION_FAILED`（Zod で先に弾く）。
- 書き込みはすべて `executions.updated_at` を更新する。承認・差し戻しは `approval_decided_by` / `approval_decided_at` も入れる。再依頼では変えない。
- 操作ログ：`execution.approved`、`execution.rejected`（`target: { type: "execution", id }`、コミットの後）。コメントはログに出さない。再依頼はログを出さない（api.md 4.5）。
- 再依頼のコメントは実行者のテキストなので、送る前に `maskReason` を通す（D-56）。差し戻しのコメントは承認者が書くのでマスクしない（置き場の値を持たない）。
- 画面：色は CSS 変数だけ。shadcn は Base UI。mutation は成功・失敗のどちらでも `["executions"]` を取り直し、エラーは帯に出す（ダイアログは閉じる）。

## Review Focus

1. **2人の承認者が同じ実行をほぼ同時に承認・差し戻す**：先の1件だけが通り、後は `STATE_CONFLICT`、画面は帯で知らせて取り直す → Task 1 のテスト「同時に承認」、Task 2 で `onError` を帯へ。
2. **承認者ロールと実行者ロールを兼ねた人が自分の実行を開く**：承認・差し戻しのボタンが出ず、API を直接呼んでも `FORBIDDEN` → Task 1「F-08 AC: 自分の実行」、Task 2 の `approvalAction` のテスト。
3. **差し戻し中に実行者ロールを外された本人が再依頼する**：`FORBIDDEN`。画面にも再依頼のボタンを出さない → Task 1「D-35」、Task 2 の `approvalAction`。
4. **承認済みの実行にコメント・エビデンス・状態の変更・再依頼・差し戻しを送る**：すべて拒否（`STATE_CONFLICT`） → Task 1「F-08 AC: 承認済み」。
5. **差し戻し中にステップの状態を変えようとする**：`STATE_CONFLICT`（コメントとエビデンスだけ追加できる） → Task 1「差し戻し後」。

| テスト名 | 流れと確かめること |
|---|---|
| `F-08 AC: 自分の実行には承認・差し戻しのボタンが出ない` | approval_checker が自分で開始・終了した実行の S-12 に「承認する」「差し戻す」がない |

| `先に別の人が承認していたら帯で知らせる` | checker の S-12 を開いたまま、API で別の承認者（beforeAll で approval_checker2 を作る）が承認 → checker が「承認する」→ 赤い帯が出て、取り直した画面は承認済み |
