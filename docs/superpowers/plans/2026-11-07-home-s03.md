# ホーム（S-03） Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** ログイン後の最初の画面で、自分が続けるべき実行・承認すべき実行・編集中の手順書を、ロールに応じた区画で1クリックで開けるようにする。

**Architecture:** API は `GET /api/me/home`。持っているロールの区画だけを返し、各区画は全件・並べ替え済み（件数が少ないので上限は画面で切る、D-16）。実行の区画は、S-11 の一覧と同じ集計（進捗など）を条件つきで使い回す。画面は `/` を置き換え、区画を縦に積む（案1）。あわせて S-11 に実行者の絞り込み（`executor`）を足す。

**Tech Stack:** Hono、Drizzle、Zod 4、React 19、TanStack Router・Query、shadcn/ui（Base UI）、Vitest、Playwright。

**Spec:**
- 配置・区画・行・並び・行き先：`../tadori-docs/design/ui.md` 9章（モックアップ `mockups/home.html` の案1）。
- 区画の条件：`../tadori-docs/design/screens.md` の S-03、D-40。S-11 の `executor`：`screens.md` の S-11、`ui.md` 9.3。
- API：`api.md` 4.2 の `GET /api/me/home`（持っているロールの区画だけ）。応答の範囲：D-49（他のユーザーは `id` と `name` だけ）。

## Global Constraints

- ブランチは `feat/home-s03`（main から）。コミットは Task ごと。範囲外：本番用の compose・Dockerfile、積み残しの軽微な点。
- 区画の出し分け：自分の実行＝`executor` ロール、承認待ち＝`approver` ロール、編集中の手順書＝`author` ロール。管理者・閲覧者のロールは区画を増やさない。
- 自分の実行＝自分が実行者で「`status = running`」か「`approvalStatus = rejected`」。承認待ち＝「`approvalStatus = pending`」で実行者が自分でない。編集中＝下書きのある手順書（未公開を含む）。
- 並び：自分の実行・編集中は最終更新の新しい順、承認待ちは終了日時の古い順。同じ日時なら `id` で決める。
- 画面は各区画の先頭 5 件（`HOME_SECTION_LIMIT = 5`）。超えたら「ほか N 件をすべて見る」。
- 文言：見出し「ホーム」、説明「続きの作業と、承認を待っている実行です」。区画名「自分の実行」「承認待ち」「編集中の手順書」。0件は「続きの作業はありません」「承認待ちの実行はありません」「編集中の手順書はありません」。どの区画もない人には「手順書と実行は、それぞれの一覧から見られます」と「手順書の一覧」「実行の一覧」のボタン。
- 「すべて見る」の行き先：`/executions?executor=<自分の id>`、`/executions?approval=pending`、`/procedures?status=editing`。
- 「パスワード変更が必要」な人は `/api/me/home` を呼べない（`/api/me` だけが例外。`app.ts` で `/me` は関門より前に付いているので、ホームの経路に `requirePasswordChanged` を個別に付ける）。
- 色は CSS 変数だけ。既存の部品（`PageHeader`、`EmptyState`、`Skeleton`、`Badge`、S-11 の進捗の棒・状態の表示）を使い回す。

## Review Focus

1. **実行者ロールと承認者ロールの両方を持つ人の、自分の承認待ちの実行**：承認待ちの区画に出ない（自分の実行の区画にも出ない。差し戻しでも実行中でもない）→ Task 1「自分が実行者の承認待ちは出ない」。
2. **差し戻された後に再依頼した実行**（`approvalStatus` が `pending` に戻る）：自分の実行から消え、他の承認者の承認待ちに出る → Task 1 の条件のテストで `rejected` と `pending` の両方を確かめる。
3. **「パスワード変更が必要」な人がホームの API を直接呼ぶ**：`PASSWORD_CHANGE_REQUIRED` → Task 1。
4. **S-12 で状態を変えたり承認したりしてからホームに戻る**：古い区画を出したままにしない → Task 2 のクエリを `staleTime: 0` にし、Task 4 の E2E で承認の後にホームから消えることを確かめる。
5. **`executor` に知らない id や壊れた値が入った S-11 の URL**：0件として扱い、チップは「実行者：不明」ではなく名前が分からなければ「実行者」とだけ出して外せる → Task 3 の filter のテストとチップの表示。

### Task 1: ホームの API

**Files:**
- Modify: `shared/src/schemas/me.ts`、`server/src/features/executions/read-service.ts`、`server/src/features/me/routes.ts`
- Create: `server/src/features/me/home-service.ts`、`server/src/features/me/home.test.ts`

**Interfaces:**
- Produces（shared）：
  - `homeExecutionSchema = executionSummarySchema.extend({ endedAt: z.iso.datetime().nullable() })`、型 `HomeExecution`
  - `homeDraftSchema = z.object({ id: z.uuid(), title: z.string(), status: z.enum(["editing", "unpublished"]), updatedBy: userRefSchema, updatedAt: z.iso.datetime() })`、型 `HomeDraft`
  - `meHomeResponseSchema = z.object({ myExecutions: z.array(homeExecutionSchema).optional(), pendingApprovals: z.array(homeExecutionSchema).optional(), drafts: z.array(homeDraftSchema).optional() })`、型 `MeHomeResponse`。ロールのない区画はキーごと返さない。
- Produces（server）：
  - `read-service.ts` に `summarizeExecutions(where?: SQL): Promise<HomeExecution[]>`（今の `listExecutions` の中身に `where` と `endedAt` を足したもの）。`listExecutions()` はこれを呼び、`endedAt` を除いて `ExecutionSummary[]` を返す（S-11 の応答は変えない）。
  - `home-service.ts` の `getHome(actor: Actor): Promise<MeHomeResponse>`。並べ替えは JS で行ってよい。

- [ ] **Step 1: 失敗するテストを書く**（`home.test.ts`。準備は `test/executions.ts` の `publishedProcedure`・`startRun` で作り、承認状態・終了日時は `db.update(executions)` で直接入れる）
  - 「ロールのない区画は返さない」：閲覧者だけ → `{}`。実行者だけ → キーは `myExecutions` だけ。作成者＋承認者 → `pendingApprovals` と `drafts`。
  - 「自分の実行は、実行中か差し戻しの自分の実行だけ」：自分の実行中・自分の差し戻し（`status: "completed", approvalStatus: "rejected"`）・自分の承認待ち・自分の完了（承認なし）・他人の実行中のうち、前の2つだけ。`updatedAt` の新しい順。`progress` が S-11 と同じ値。
  - 「承認待ちは、実行者が自分でないものだけ、終了日時の古い順」：実行者＋承認者ロールの人で、自分の承認待ちは出ず、他人の承認待ち2件が `endedAt` の古い順。
  - 「編集中の手順書は下書きのある手順書（未公開を含む）」：公開済み＋下書き → `status: "editing"`、未公開 → `"unpublished"`、下書きのない公開済みは出ない。`title` は下書きの文書から、`updatedBy` は `{ id, name }` だけ。
  - 「パスワード変更が必要な人は呼べない」：`createUser({ …, mustChangePassword: true })` → 403 と `PASSWORD_CHANGE_REQUIRED`（`session.test.ts` の確かめ方に合わせる）。
