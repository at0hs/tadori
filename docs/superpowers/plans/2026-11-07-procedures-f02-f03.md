# 手順書の作成・編集・版管理（F-02、F-03） Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 手順書の API（`features/procedures`）と画面 S-04〜S-09 を作り、手順書を作成・編集・保存・公開・破棄・アーカイブし、版の履歴を見られるようにする。

**Architecture:** 手順書の文書は `shared/` の Zod スキーマ（`ProcedureContent`）を正本とし、保存時の検証はスキーマ、公開時の検証（未定義の変数・手順が0件）は `shared/` の関数で行い、画面とサーバーで同じものを使う。サーバーは `procedures` の行を `FOR UPDATE` でロックしてから、`revision`（下書きがあるとき）か版数（ないとき、D-55）で照合する。画面の編集は React Hook Form で文書を丸ごと持ち、欄は CodeMirror 6、並べ替えは dnd-kit。

**Tech Stack:** Hono、Drizzle 1.0 RC、Zod 4、`uuid`（v7）、React 19、TanStack Router・Query、React Hook Form、CodeMirror 6（`@codemirror/state`・`view`・`autocomplete`・`commands`）、dnd-kit（`@dnd-kit/core`・`sortable`・`utilities`）、react-markdown、Base UI の Combobox、Vitest、Playwright。

**Spec:**
- 画面の配置と見せ方：`../tadori-docs/design/ui.md` 7章（承認済み）。見た目の正本は `../tadori-docs/design/mockups/procedures.html`。
- 画面の内容：`../tadori-docs/design/screens.md` S-04〜S-09、4章、8章。
- API：`../tadori-docs/design/api.md` 3章・4.3。状態と操作：`state-transitions.md` 2章。文書とテーブル：`data-model.md` 3章・4.2。権限：`authorization.md` 3.2。
- 要件：`../tadori-docs/requirements.md` F-02、F-03、F-04 の変数の規則。設計判断：D-05、D-06、D-07、D-09、D-17、D-24、D-26〜D-29、D-32、D-34、D-49、D-55、D-58。

## Global Constraints

- ブランチは `feat/procedures-f02-f03`（main から）。コミットは Task ごと。
- 文言は日本語。データ・例はダミーだけ（`example.test` など）。
- アプリのテーブルの ID は UUID v7 をアプリ側で振る（D-27）。ステップの `id` も画面で v7 を振る。どちらも `shared/src/ids.ts` の `newId()` を使う。
- 時刻の列は `timestamp({ withTimezone: true })`。テーブルは `snakeCase.table(...)`。適用済みのマイグレーションは書き換えない。
- 変数名の規則（D-06）：`/^[A-Za-z][A-Za-z0-9_-]{0,63}$/`。大文字小文字は区別して参照するが、大文字小文字だけが違う名前は定義できない。`##{name}` はエスケープ、規則に合わない `#{...}` はただの文字列。
- 置換の対象（＝未定義の変数を調べる対象）は、ステップの `title`・`description`・`command`・`verification`（手順と切り戻しの両方）だけ。基本情報・前提条件・変数の説明は対象外。
- 秘密変数は `default: null`（D-26）。
- 応答の決まり（D-49、api.md 3章）：下書きの中身は `GET /api/procedures/{id}/draft` だけが返す。一覧・詳細のタイトル・タグは最新版の文書から取る（未公開は下書きから、作成者にだけ）。下書きの最終更新者・日時は作成者ロールの人にだけ返す。他のユーザーは `{ id, name }` だけ。
- 状態を変える API はすべて作成者ロール（`requireRole("author")`）。閲覧の API は全員。
- 操作ログは `procedure.published`（`versionNo` を付ける）と `procedure.archived` だけ。コミットの後に出す。
- 画面：色は CSS 変数だけ。画面の移動はリンク（`<Link className={buttonVariants()}>`）。Enter で何かをする処理は `isComposing` なら何もしない。shadcn は Base UI（`render`、`asChild` なし）。
- 新しい依存は、出てから24時間以上たった版を入れる（`minimumReleaseAge`）。pnpm が `minimumReleaseAgeExclude` を書き足したらコミットしない。

## Review Focus

1. **同じ版から2人が編集を始め、片方が保存して公開した後に、もう片方が保存する**（D-55）：`DRAFT_CONFLICT` になり、公開者と公開日時が付く → Task 5 のテスト「D-55」。
2. **2人が同じ `revision` で同時に保存する**：片方だけが通り、もう片方は `DRAFT_CONFLICT` → Task 5 の同時実行のテスト（2つの接続）。
3. **作成者ロールのない人が未公開の手順書を探る**（一覧・詳細・版・下書き）：一覧に出ず、詳細と版は `NOT_FOUND`、下書きは `FORBIDDEN`。公開済みの手順書の詳細に、下書きの最終更新者・日時が出ない → Task 4 のテスト「D-34／D-49」。
4. **`host` を定義して `#{Host}` と書く／`Host` と `host` を両方定義する**：前者は公開時に未定義の変数、後者は保存時のエラー（後の方の `name` に出す）→ Task 2 のテスト。
5. **タグや変数の欄で、日本語の変換を確定する Enter**：タグが増えない。IME が ON のまま `#{` と打つと「＃｛」が「#{」に直り、候補が出る（D-58）→ Task 8 の `fixFullwidthOpen` のテスト、Task 9 のタグ入力の `isComposing`。

  - `procedureContentSchema`（保存時の検証）：`{ title: string(trim, 1〜200), summary: string(≤1000), tags: string(trim,1〜50)[] (≤20, 重複不可), prerequisites: string(≤20000), variables: ProcedureVariable[] (≤100), steps: ProcedureStep[] (≤500), rollbackSteps: ProcedureStep[] (≤500) }`。`superRefine` で：変数名を小文字にして重複 → 後の方の `variables.<i>.name` に「同じ名前の変数があります（大文字と小文字の違いだけの名前も使えません）。」、ステップの `id` が手順と切り戻しを通して重複 → 後の方の `<steps|rollbackSteps>.<i>.id`。タイトル未入力は「タイトルを入力してください。」（手順書・ステップとも）。
  - `type ProcedureContent`、`type ProcedureStep`、`type ProcedureVariable`
  - `findPublishErrors(content: ProcedureContent): { path: string; message: string }[]` — `steps` が空なら `{ path: "steps", message: "公開するには、手順のステップが1つ以上必要です。" }`。各ステップの4つの欄の未定義の参照ごとに `{ path: "steps.2.command", message: "未定義の変数 #{hostname} を参照しています。" }`（同じ欄に同じ名前が複数あっても1つ）。
  - `procedureStatusSchema = z.enum(["unpublished", "published", "editing", "archived"])`
  - `userRefSchema = { id: z.string(), name: z.string() }`
  - `draftLockSchema = z.union([{ revision: z.number().int().positive() }, { revision: z.null(), versionNo: z.number().int().positive() }])`（読み込んだ時点の照合の材料。D-05、D-55）

    - `ProcedureListResponse = { procedures: { id, title, summary, tags, status, latestVersionNo: number|null, lastPublishedAt: string|null }[] }`
    - `ProcedureDetailResponse = { id, status, latestVersion: { versionNo, content, publishedBy: UserRef, publishedAt, changeReason } | null, draft: { updatedBy: UserRef, updatedAt } | null }`（`draft` は作成者ロールの人で下書きがあるときだけ値を持つ）
    - `ProcedureVersionListResponse = { title, versions: { versionNo, changeReason, publishedBy, publishedAt }[] }`
    - `ProcedureVersionResponse = { title, versionNo, content, publishedBy, publishedAt, changeReason, latestVersionNo }`
    - `DraftResponse = { status, content, lock: DraftLock, baseVersionNo: number|null, updatedBy: UserRef|null, updatedAt: string|null }`
    - `CreateProcedureRequest = { content }` → `{ id, revision: 1 }`
    - `SaveDraftRequest = { content, lock }` → `{ revision, updatedBy, updatedAt }`
    - `PublishRequest = { content, lock, changeReason: string(trim, 1〜1000、未入力は「変更理由を入力してください。」) }` → `{ versionNo }`
    - `discardDraftQuerySchema = { revision: z.coerce.number().int().positive() }` → `{ deleted: "draft" | "procedure" }`
    - `procedureIdParamSchema = { id: z.uuid() }`、`versionParamSchema = { id: z.uuid(), versionNo: z.coerce.number().int().positive() }`
