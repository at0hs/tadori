# F-11 下書きの変更点（S-17）Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 保存された下書きと最新版の違いを、新しい画面 S-17 に1列で出し、そこから公開できるようにする。S-05・S-09 から開けるようにし、S-09 の公開のダイアログに変更の要約を出す。

**Tech Stack:** React 19、TanStack Router・Query、shadcn/ui（Base UI）、Tailwind v4、jsdiff（npm の `diff` 9.0.0）、Vitest、Playwright。

**Spec:** `../tadori-docs/requirements.md` の F-11、`../tadori-docs/design/decisions.md` の D-66、`../tadori-docs/design/screens.md` の S-17、`../tadori-docs/design/ui.md` の 10章、モックアップ `../tadori-docs/design/mockups/diff.html`（「案1」）。

ブランチ：`feat/draft-diff-f11`（main から）。

## Global Constraints

- 色は `web/src/index.css` の CSS 変数だけ（追加＝`success`、削除＝`destructive`、変更＝`warning`、移動＝`primary`／`accent`）。`bg-green-*` などを書かない。
- ロールの判定は shared の `can(role, permission)`。S-17 を開けるのは `editProcedure`（作業者以上）、公開は `publishProcedure`（承認者以上）。
- 画面の移動はリンク（`<Link className={buttonVariants(...)}>`）。
- 比べるのは「保存された下書き」と「最新版」だけ。S-09 の公開のダイアログの要約だけは、画面の今の内容と最新版を比べる。
- ステップは `id`、変数は `name` で突き合わせる。手順と切り戻し手順は別々に比べる（手順から切り戻しへ移ったステップは、手順で削除・切り戻しで追加になる）。
- 移動は「両方にあるステップのうち、並びの最長共通部分列に入らないもの」。番号がずれただけでは移動にしない。
- 説明・前提条件は Markdown だが、差分では書いたままの文字を出す（Markdown として描かない）。`#{変数名}` の色付けは `VarText` と同じ見た目。
- 文の差分は `diffWords(a, b, { intlSegmenter: new Intl.Segmenter("ja", { granularity: "word" }) })`。コマンドと前提条件は `diffLines` で、行の中の違いは同じ数の削除行と追加行が続くところだけ `diffWords` で求める。
- 文言はモックアップと ui.md 10章のとおり（下の各タスクに書いた文言をそのまま使う）。
- `diff` は `web/package.json` の dependencies に `9.0.0` で入れる（型は同梱）。

## Review Focus

1. 日本語の文（空白なし）で、差分の部品をつなぐと元の文に戻らない → `textDiff` は same＋del で前の文、same＋add で後の文にぴったり戻る（Task 1 のテスト）。
2. コマンドの末尾の改行・空白だけが変わった → 「変更」として出て、違いが見える（Task 1 のテスト）。
3. 変数の名前を変えた／秘密かどうかだけ変えた → 名前を変えたら旧名の削除と新名の追加、秘密だけ変えたら「変更」（Task 1 のテスト）。
4. 手順のステップを全部消した・切り戻しが前は空だった → 全部が削除／追加として出て、0件の区画でも落ちない（Task 1 のテスト）。
5. S-17 を開いている間に下書きが保存し直された・公開された → 公開しようとすると古い内容を公開せず、誰がいつ変えたかと「読み込み直す」を出す（Task 4 のテスト・E2E）。

```ts
export type DiffKind = "same" | "add" | "del";
export type TextPart = { kind: DiffKind; text: string };
/** 1行。kind が same 以外の行で、対になる行があれば parts に行の中の違いが入る。なければ1つの部品。 */
export type LinePart = { kind: DiffKind; parts: TextPart[] };
export type ItemStatus = "same" | "add" | "del" | "mod";

export type StepDiff = {
  id: string;
  status: ItemStatus;       // add / del / mod（中身が違う）/ same
  moved: boolean;           // status が same でも mod でも true になりうる
  oldNo: number | null;     // 最新版での番号（1始まり）。追加なら null
  newNo: number | null;     // 下書きでの番号。削除なら null
  title: TextPart[];
  description: TextPart[];
  command: LinePart[];
  verification: TextPart[];
  evidenceRequired: { before: boolean | null; after: boolean | null }; // 追加は before null、削除は after null
};
export type VariableDiff = {
  name: string;
  status: ItemStatus;
  before: ProcedureVariable | null;
  after: ProcedureVariable | null;
  description: TextPart[];
};
export type TagDiff = { tag: string; kind: DiffKind };
export type ProcedureDiff = {
  title: TextPart[];
  summary: TextPart[];
  tags: TagDiff[];          // 下書きの順、その後に消えたタグを最新版の順で
  prerequisites: LinePart[];
  variables: VariableDiff[]; // 下書きの順、消えた変数は Step 4 の規則の位置
  steps: StepDiff[];
  rollbackSteps: StepDiff[];
  changed: boolean;          // どこかに違いがあるか
};

export function textDiff(before: string, after: string): TextPart[];
export function lineDiff(before: string, after: string): LinePart[];
export function isChanged(parts: TextPart[] | LinePart[]): boolean;
export function diffProcedure(base: ProcedureContent, draft: ProcedureContent): ProcedureDiff;
```

```ts
describe("textDiff", () => {
  it("日本語の文でも、部品をつなぐと前後の文に戻る", () => {
    const a = "設定を再読み込みする";
    const b = "設定を再読み込みして worker 数を確かめる";
    const parts = textDiff(a, b);
    expect(parts.filter((p) => p.kind !== "add").map((p) => p.text).join("")).toBe(a);
    expect(parts.filter((p) => p.kind !== "del").map((p) => p.text).join("")).toBe(b);
    expect(parts[0]).toMatchObject({ kind: "same" });
    expect(parts[0].text.startsWith("設定を")).toBe(true);
  });
  it("同じ文なら same が1つ、空同士なら空配列", () => {
    expect(textDiff("同じ", "同じ")).toEqual([{ kind: "same", text: "同じ" }]);
    expect(textDiff("", "")).toEqual([]);
  });
});

describe("lineDiff", () => {
  it("変わった行だけ del と add になり、対の行には行の中の違いが入る", () => {
    const lines = lineDiff("ssh #{host} sudo sed -i \\\n  /etc/nginx/nginx.conf", "ssh #{host} sudo sed -i.orig \\\n  /etc/nginx/nginx.conf");
    expect(lines.map((l) => l.kind)).toEqual(["del", "add", "same"]);
    expect(lines[1].parts.some((p) => p.kind === "add" && p.text.includes(".orig"))).toBe(true);
    expect(lines[2].parts).toEqual([{ kind: "same", text: "  /etc/nginx/nginx.conf" }]);
  });
  it("末尾の改行だけが違っても違いとして出る", () => {
    expect(isChanged(lineDiff("echo ok\n", "echo ok"))).toBe(true);
  });
});

describe("diffProcedure：ステップ", () => {
  // 最新版 [a, b, c, d]、下書き [c, b(タイトル変更), d, e(追加)]、a は削除
  it("ID で突き合わせ、追加・削除・変更・移動を決める", () => {
    const d = diffProcedure(content({ steps: [A, B, C, D] }), content({ steps: [C, { ...B, title: "新しい題" }, D, E] }));
    expect(d.steps.map((s) => [s.id, s.status, s.moved, s.oldNo, s.newNo])).toEqual([
      [C.id, "same", true, 3, 1],
      [A.id, "del", false, 1, null],
      [B.id, "mod", false, 2, 2],
      [D.id, "same", false, 4, 3],
      [E.id, "add", false, null, 4],
    ]);
  });
  it("前に足しただけで番号がずれたステップは移動にしない", () => {
    const d = diffProcedure(content({ steps: [A, B] }), content({ steps: [E, A, B] }));
    expect(d.steps.filter((s) => s.moved)).toEqual([]);
  });
  it("2つを入れ替えたら、移動は1つだけ", () => {
    const d = diffProcedure(content({ steps: [A, B] }), content({ steps: [B, A] }));
    expect(d.steps.filter((s) => s.moved)).toHaveLength(1);
  });
  it("エビデンス必須だけを変えても mod、前後の値を持つ", () => {
    const d = diffProcedure(content({ steps: [A] }), content({ steps: [{ ...A, evidenceRequired: true }] }));
    expect(d.steps[0]).toMatchObject({ status: "mod", evidenceRequired: { before: false, after: true } });
  });
  it("手順を全部消すと全部が削除、空だった切り戻しに足すと追加", () => {
    const d = diffProcedure(content({ steps: [A, B] }), content({ steps: [], rollbackSteps: [E] }));
    expect(d.steps.map((s) => s.status)).toEqual(["del", "del"]);
    expect(d.rollbackSteps.map((s) => s.status)).toEqual(["add"]);
  });
});

describe("diffProcedure：変数・タグ・全体", () => {
  it("名前を変えた変数は旧名の削除と新名の追加、秘密かどうかだけの変更は mod", () => {
    const host = { name: "host", description: "対象", default: "web01.example.test", secret: false };
    const pw = { name: "pw", description: "", default: null, secret: false };
    const d = diffProcedure(content({ variables: [host, pw] }), content({ variables: [{ ...host, name: "target" }, { ...pw, secret: true }] }));
    expect(d.variables.map((v) => [v.name, v.status])).toEqual([["target", "add"], ["host", "del"], ["pw", "mod"]]);
  });
  it("タグは下書きの順、消えたタグは後ろ", () => {
    const d = diffProcedure(content({ tags: ["nginx", "定期作業"] }), content({ tags: ["監視", "nginx"] }));
    expect(d.tags).toEqual([{ tag: "監視", kind: "add" }, { tag: "nginx", kind: "same" }, { tag: "定期作業", kind: "del" }]);
  });
  it("同じ文書なら changed は false", () => {
    const c = content({ steps: [A, B], variables: [] });
    expect(diffProcedure(c, structuredClone(c)).changed).toBe(false);
  });
});
```

- [ ] **Step 4: `compute.ts` を書く**

- `textDiff`：Global Constraints の `diffWords` の呼び方。jsdiff の `added`/`removed` を `kind` に写し、空の部品は捨てる。
- `lineDiff`：`diffLines` の結果を1行ずつに割る（末尾の改行の有無は、最後の行に `"\n"` を残すなどして違いが消えないようにする）。削除の行の並びの直後に同じ数の追加の行が続くところは、i 番目同士を `textDiff` にかけ、削除の行には same＋del、追加の行には same＋add の部品を入れる。
- ステップの並び（手順・切り戻しそれぞれ）：
  1. 両方にある ID について、最新版の並びと下書きの並びの最長共通部分列を DP で求める。共通部分列に入らないものを `moved: true`。長さが同じ候補が複数あるときは、後ろからの DP 表 `L[i][j]`（最新版の i 番目以降と下書きの j 番目以降）を先頭からたどり、一致しないところで `L[i+1][j] === L[i][j+1]` なら下書きの側（j）を進める。こうすると「前へ動かしたステップ」が移動になる（テストの [a,b,c,d]→[c,b,d,e] で c が移動）。
  2. 出す順は下書きの順。削除したステップは「最新版でその後ろにあり、下書きにも残っていて `moved` でない最初のステップ」の直前に入れる。なければ最後。削除が続くときは最新版の順を保つ。
  3. `status` は、片方にしかなければ add / del、両方にあって title・description・command・verification・evidenceRequired のどれかが違えば mod、ほかは same。
- 変数の並び：下書きの順。消えた変数はステップと同じく「最新版でその後ろにあり、下書きにも残っている最初の変数」の直前（なければ最後）。`mod` は description・default・secret のどれかが違うとき。
- `changed`：title・summary・prerequisites のどれかに違いがある、タグに same 以外がある、変数・ステップに same 以外か `moved` がある。

- [ ] **Step 2: 部品を書く**（`diff-parts.tsx`）

- `InlineDiff({ parts })`：same はそのまま、del は `<del className="rounded-sm bg-destructive/15 px-px line-through decoration-destructive/70">`、add は `<ins className="rounded-sm bg-success/20 px-px no-underline">`。どの部品の中でも `#{変数名}` は `VarText` で色付けする。

- 基本情報・前提条件・変数のカードは、違いがあるときだけ出し、見出しに `ChangeBadge kind="mod"`。基本情報はタイトル・概要（違うものだけ `InlineDiff`）とタグ（違いがあれば全部のタグを、消えたタグは赤い取り消し線のバッジ、足したタグは緑のバッジで）。前提条件は足した行・消した行だけを出し、隠した数を「変更のない {n} 行を隠しています」と添える。変数は違う変数だけの表（変数・説明・既定値・印）。既定値の違いは `BeforeAfter`、秘密変数は既定値の代わりに「秘密」のバッジ、秘密かどうかの違いは「秘密：なし → あり」。
- 手順・切り戻し手順のカードは常に出す。見出しに「{下書きの数} ステップ（v{N} は {最新版の数}）」。ステップは `<ol>`。1つのステップは `id={"diff-step-" + id}`、左の太い線（add＝`border-l-success`、del＝`border-l-destructive`、moved＝`border-l-primary`、mod＝`border-l-warning`、same＝透明）、番号の丸（削除は最新版の番号を取り消し線で `bg-destructive/10 text-destructive`）、バッジ（mod か add/del、moved なら移動も並べる）、タイトル・説明・コマンド（`LineDiffBlock`。違いがなければ今の `<pre>` の見た目）・確認方法・エビデンス必須（違えば「エビデンス必須：」＋`BeforeAfter`、同じなら今のバッジ）。追加は `bg-success/5`、削除は `bg-destructive/5`、削除のタイトルは取り消し線。
- 変更のないステップ（`status === "same" && !moved`）が続くところは1行にまとめ、「変更のないステップ {n} 件（{番号を「・」でつなぐ}）を表示」のボタン（`ChevronsUpDown`）を出す。押したらその場所だけ開く（状態はカードの中の `useState`）。
