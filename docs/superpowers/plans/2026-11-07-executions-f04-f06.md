# 変数・実行・ステップの記録（F-04、F-05、F-06） Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 公開済みの手順書から実行を開始し（S-10）、変数を置換した実行手順書を見ながらステップの状態・コメント・エビデンスを記録して、終了・中止できるようにする（S-12）。S-11 実行の一覧と、S-15 の「実行中の実行」（D-36）も足す。

**Architecture:** 実行は版と秘密でない変数の値だけを持ち、実行手順書は画面が `shared/` の置換で都度作る（D-23）。秘密変数の値はサーバーに送らず、タブのメモリの置き場（`secret-store.ts`、D-41）だけに置き、実行者が入力するテキストは送る前に置き場の値でマスクする（D-02、D-56）。サーバーは `executions` の行を `FOR UPDATE` でロックしてから、本人・状態を確かめ、ステップの状態は画面が見ていた状態と照合する（D-46）。

**Tech Stack:** Hono、Drizzle 1.0 RC、Zod 4、React 19、TanStack Router・Query、React Hook Form、shadcn/ui（Base UI。`toggle-group`・`dialog`・`alert-dialog`）、Vitest、Playwright。新しい依存は入れない。

**Spec:**
- 画面の配置と見せ方：`../tadori-docs/design/ui.md` 8章（承認済み）。見た目の正本は `../tadori-docs/design/mockups/executions.html`（S-12 は案2、状態の操作は A、幅は標準）。
- 画面の内容：`../tadori-docs/design/screens.md` S-10〜S-12、S-15、4〜6章、8章。
- API：`api.md` 3章・4.4・4.6・5.1・5.2。状態と操作：`state-transitions.md` 1章・3章・4章。テーブル：`data-model.md` 4.3・5章。権限：`authorization.md` 2章・3.3。排他とログ：`conventions.md` 4章・6.2・6.3。
- 要件：`../tadori-docs/requirements.md` F-04〜F-07、4.1。設計判断：D-01〜D-04、D-23〜D-25、D-27、D-35、D-36、D-41、D-43、D-46、D-48、D-49、D-56、D-57。

## Global Constraints

- ブランチは `feat/executions-f04-f06`（main から）。コミットは Task ごと。
- 範囲外：承認・差し戻し・再依頼の API と画面の操作（F-08）、Excel 出力（F-09）、ホームの区画（S-03）。ただし終了したら承認待ちにする（`approval_events` に `requested` を入れる）ところまでは作る。差し戻しの状態でのコメント・エビデンスの追加の条件も、サービスには入れておく。
- 文言は日本語。データ・例はダミーだけ（`example.test`、`Dummy-Pass-123` など）。
- テーブルの ID は `newId()`（UUID v7）。時刻の列は `timestamp({ withTimezone: true })`。テーブルは `snakeCase.table(...)`。状態は文字列の列と CHECK 制約（D-27）。適用済みのマイグレーションは書き換えない。
- 値の名前：実行 `running` / `completed` / `abnormal` / `cancelled`、ステップ `pending` / `done` / `skipped` / `failed`、区分 `main` / `rollback`、承認 `pending` / `approved` / `rejected`、承認の履歴 `requested` / `approved` / `rejected`。
- 秘密変数：値をリクエストで受け取らない（名前が来たら `VALIDATION_FAILED`、D-49）。マスクは `●●●●`（`SECRET_MASK`）。値の最低文字数は 4（`SECRET_MIN_LENGTH`、ui.md 8.2）。
- 長さの上限：変数の値 1000、コメント 5000、エビデンス 20000、スキップの理由・中止の理由 1000（api.md 6章で実装に回したもの）。
- 実行への書き込みはすべて `executions.updated_at` を更新する（state-transitions.md 1章）。
- 操作ログ：`execution.started`（`versionNo`）、`execution.finished`（`status`）、`execution.cancelled`（`by: "executor" | "admin"`。理由は管理者のときだけ `reason` で出す、D-56）。`target: { type: "execution", id }`。コミットの後に出す。実行者が入力したテキストはログに出さない（conventions.md 6.3）。
- 応答（D-49）：他のユーザーは `{ id, name }` だけ。`canAdminCancel` は管理者にだけ項目ごと返す。実行者のテキストはそのまま返す（サーバーで変換しない）。
- 画面：色は CSS 変数だけ。移動はリンク。Enter で何かをする処理は `isComposing` なら何もしない。shadcn は Base UI（`render`、`asChild` なし）。秘密変数の値を `localStorage`・`sessionStorage`・IndexedDB・Cookie・URL に書かない。

## Review Focus

1. **同じ実行を2つのタブで開き、片方で状態を変えた後、もう片方で変える**：`STEP_STATUS_CONFLICT`（今の状態と変えた人・日時つき）になり、画面は帯で知らせて取り直す → Task 4 のテスト「D-46」、Task 9 の帯。
2. **実行の途中で実行者ロールを剥奪された／無効化された**：本人の操作はすべて `FORBIDDEN`。管理者はそうなってから初めて中止でき（理由必須）、それまでは `FORBIDDEN` → Task 5 のテスト「D-35／D-36」。
3. **秘密変数の値がコメント・スキップの理由・中止の理由に紛れ込む／値が別の秘密変数の値を含む／値に正規表現の記号（`.`・`*`・`$`）がある**：長い値から順に文字どおりに置き換える → Task 1 の `maskSecrets` のテスト、Task 9・10 で送る前に必ず通す。
4. **コマンドに `##{host}`・`#{a b}`・未入力の秘密変数がある**：コピーは `#{host}`・`#{a b}` をそのまま入れ、秘密変数の値が置き場になければコピーさせない → Task 7 の `textForCopy` のテスト。
5. **S-10 を開いている間に新しい版が公開された／アーカイブされた**：開始は `NOT_LATEST_VERSION`／`STATE_CONFLICT` で、実行はできない → Task 3 のテスト、Task 8 の帯。

### Task 4: 変数・ステップの状態・コメント・エビデンスの API
